# 1과목. 데이터 모델링의 이해 (요약)

## 1장. 데이터 모델링의 이해

### 데이터 모델링 개념
- **정의:** 현실 세계의 업무를 데이터 관점에서 추상화하여 표현하는 과정
- **특징:** 추상화, 단순화, 명확화
- **유의점:** 중복(Duplication), 비유연성(Inflexibility), 비일관성(Inconsistency)
- **관점:** 데이터 관점(What), 프로세스 관점(How), 데이터와 프로세스의 상관 관점(CRUD 매트릭스)

### 모델링 단계

| 단계 | 핵심 |
|---|---|
| 개념적 모델링 | 추상화 수준이 가장 높음. 업무 중심, 전사적 관점, 핵심 엔터티와 관계 도출 |
| 논리적 모델링 | 키, 속성, 관계를 정확히 표현. **정규화** 수행. 재사용성이 높음 |
| 물리적 모델링 | 실제 DB에 맞게 테이블, 인덱스, 저장 구조 설계. 성능 고려 |

### 3층 스키마 (ANSI-SPARC)와 데이터 독립성

| 스키마 | 관점 |
|---|---|
| 외부 스키마 | 사용자(응용 프로그램) 관점. 뷰(View) |
| 개념 스키마 | 통합 관점. 전체 DB의 논리 구조, 모든 사용자의 데이터를 통합 |
| 내부 스키마 | 물리적 저장 관점. 실제 저장 구조 |

- **논리적 독립성:** 개념 스키마가 바뀌어도 외부 스키마는 영향 없음
- **물리적 독립성:** 내부 스키마가 바뀌어도 개념 스키마는 영향 없음
- **사상(Mapping):** 외부-개념 = 논리적 사상, 개념-내부 = 물리적 사상

### ERD
- 1976년 피터 첸(Peter Chen)이 제안
- 표기법: Chen, IE(Information Engineering, 까마귀발), Barker
- 작성 순서: 엔터티 도출 → 엔터티 배치 → 관계 설정 → 관계명 기술 → 관계 참여도(차수) 기술 → 관계 필수 여부 기술

## 엔터티 (Entity)

### 특징 (시험에 자주 나옴)
1. 업무에서 필요하고 관리하고자 하는 정보
2. 유일한 식별자로 식별 가능
3. **2개 이상의 인스턴스** 집합
4. 업무 프로세스에서 이용됨
5. 반드시 **속성**을 가짐
6. 다른 엔터티와 **최소 1개 이상 관계**를 가짐 (단, 통계성/코드성 엔터티 등은 관계 생략 가능)

### 분류

| 기준 | 종류 | 예시 |
|---|---|---|
| 유무형 | 유형 엔터티: 물리적 형태 있음 | 사원, 물품 |
| | 개념 엔터티: 물리적 형태 없는 개념 | 조직, 보험상품 |
| | 사건 엔터티: 업무 수행 중 발생 | 주문, 청구 |
| 발생 시점 | 기본(키) 엔터티: 독립적으로 생성, 다른 엔터티의 부모 | 사원, 부서, 상품 |
| | 중심(메인) 엔터티: 기본 엔터티에서 발생, 업무의 중심 | 계약, 주문 |
| | 행위 엔터티: 2개 이상의 부모에서 발생, 자주 변경되고 양이 많음 | 주문 목록, 사원 변경 이력 |

### 명명 규칙
현업에서 쓰는 용어 사용, 약어 지양, **단수 명사**, 모델 내에서 유일, 생성 의미대로 부여

## 속성 (Attribute)
- **정의:** 업무에서 관리할, 의미상 더 이상 분리되지 않는 최소 데이터 단위
- 하나의 속성은 하나의 인스턴스에서 **하나의 값만** 가짐
- 엔터티 1 : 인스턴스 N, 인스턴스 1 : 속성 N, 속성 1 : 속성값 1

### 분류

| 기준 | 종류 |
|---|---|
| 특성 | **기본 속성**(업무에서 원래 존재), **설계 속성**(코드, 일련번호처럼 설계 시 만든 것), **파생 속성**(다른 속성에서 계산된 값. 정합성 문제로 최소화) |
| 구성 방식 | PK 속성, FK 속성, 일반 속성 |
| 분해 여부 | 단일 속성, 복합 속성(예: 주소 = 시 + 구 + 동), 다중값 속성 |

- **도메인:** 속성이 가질 수 있는 값의 범위 (데이터 타입, 크기, 제약조건)

---

## 관계 (Relationship)
- **존재에 의한 관계**(예: 사원은 부서에 소속) / **행위에 의한 관계**(예: 고객이 주문)
  - ERD는 둘을 구분하지 않음. UML 클래스 다이어그램은 연관 관계 / 의존 관계로 구분
- **관계 구성 요소:** 관계명, 관계 차수(Cardinality: 1:1, 1:M, M:N), 관계 선택 사양(Optionality: 필수 / 선택)
- **관계 정의 시 체크사항**
  - 두 엔터티 사이에 관심 있는 연관 규칙이 있는가
  - 두 엔터티 사이에 정보의 조합이 발생하는가
  - 업무 기술서, 장표에 관계 연결 규칙이 서술되어 있는가
  - 관계를 연결하는 **동사**가 있는가

## 식별자 (Identifier)

### 주식별자의 특징 (암기)

| 특징 | 의미 |
|---|---|
| 유일성 | 모든 인스턴스를 유일하게 구분 |
| 최소성 | 구성 속성 수가 유일성을 만족하는 최소 |
| 불변성 | 한 번 정해지면 값이 바뀌지 않음 |
| 존재성 | 반드시 값이 존재 (NULL 불가) |

### 분류

| 기준 | 종류 |
|---|---|
| 대표성 | 주식별자 / 보조식별자 |
| 생성 여부 | 내부식별자(엔터티 내부에서 생성) / 외부식별자(다른 엔터티와 관계로 받은 것, FK) |
| 속성 수 | 단일식별자 / 복합식별자 |
| 대체 여부 | 본질식별자(업무에서 만들어진 것) / 인조식별자(인위적으로 만든 것, 예: 일련번호) |

### 주식별자 도출 기준
- 업무에서 자주 이용되는 속성
- 명칭, 내역처럼 이름으로 기술되는 것은 피함
- 복합식별자는 속성이 너무 많지 않게

### 식별 관계 vs 비식별 관계

| 구분 | 식별 관계 | 비식별 관계 |
|---|---|---|
| 부모 PK가 자식에서 | **자식 PK의 일부** | 자식의 **일반 속성** |
| 표기 | 실선 | 점선 |
| 연결 강도 | 강함 | 약함 |
| 단점 | 계속 쓰면 자식 PK 속성이 많아져 복잡 | 계속 쓰면 부모 정보 조회에 조인이 많아짐 |

- **비식별 관계를 고려하는 경우:** 자식이 부모 없이 생성될 수 있음, 부모가 삭제되어도 자식이 남아야 함, 자식 PK를 독립적으로 구성하고 싶을 때

## 2장. 데이터 모델과 SQL

### 정규화
- **목적:** 데이터 중복을 줄이고 **이상 현상**(삽입 이상, 갱신 이상, 삭제 이상)을 제거

| 단계 | 조건 |
|---|---|
| 1NF | 모든 속성이 **원자값**, 반복 그룹 제거 |
| 2NF | **부분 함수 종속** 제거 (복합 PK의 일부에만 종속된 속성 분리) |
| 3NF | **이행 함수 종속** 제거 (A → B → C 에서 C 분리) |
| BCNF | 모든 결정자가 후보키 |
| 4NF / 5NF | 다치 종속 제거 / 조인 종속 제거 |

- 정규화하면 입력, 수정, 삭제 성능은 좋아지고, 조회는 조인이 늘어 느려질 수 있음 (항상 느려지는 것은 아님)
- **반정규화:** 조회 성능을 위해 의도적으로 중복을 허용 (테이블 병합/분할, 중복 컬럼, 파생 컬럼, 이력 테이블 등)

### 관계와 조인의 이해
- 관계는 조인의 근거. 부모의 PK와 자식의 FK로 조인
- **계층형 데이터 모델:** 같은 엔터티 안에서 상하 관계 (예: 사원-관리자) → **셀프 조인**
- **상호 배타적 관계(Arc):** 자식이 여러 부모 중 하나와만 관계 (예: 주문은 개인고객 또는 법인고객 중 하나)

### 모델이 표현하는 트랜잭션
- **트랜잭션:** 하나의 논리적 작업 단위. 함께 처리되어야 하는 업무는 한 트랜잭션
- **ACID:** 원자성(Atomicity), 일관성(Consistency), 고립성(Isolation), 지속성(Durability)
- 모델에서는 **필수 관계**로 표현 (예: 주문과 주문상품은 반드시 함께 생성)

### NULL 속성의 이해
- NULL은 **값이 없음 / 모름**. 공백(' ')이나 0과 다름
- 산술 연산에 NULL이 있으면 결과는 **NULL**
- 비교 연산 결과는 **Unknown** → `= NULL` 안 됨, 반드시 `IS NULL` / `IS NOT NULL`
- 집계 함수는 NULL을 **제외**하고 계산 (`COUNT(*)`만 NULL 포함 행 수)
- 정렬: **Oracle은 NULL을 가장 큰 값**(ASC 시 맨 뒤), SQL Server는 가장 작은 값
- Oracle에서는 빈 문자열 `''`도 NULL로 취급

### 본질식별자 vs 인조식별자
- **인조식별자 장점:** 단순, 편리, PK가 짧음
- **인조식별자 단점:** 본질식별자에 유니크 제약이 없으면 **중복 데이터 발생 가능**, 불필요한 인덱스가 추가됨
- 꼭 필요할 때만 사용
